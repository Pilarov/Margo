# ADR-015: Margo — сервис памятей; documents/RAG вне области

**Status**: Proposed
**Date**: 2026-09-24
**Deciders**: dspilarov (продуктовое решение) + opencode
**Supersedes (в части)**: ADR-007 (второй вход/документные слои), ADR-013 (§Pending про `retriever.ts`), ADR-014 (документные модули карты)

## Context

Margo отвечает на вопрос «что система помнит об этом проекте/пользователе» — и делает это на **горячем
пути**: памяти вызываются и обновляются на каждый вызов агента, то есть latency-critical. Документы
отвечают на другой вопрос («что написано в источниках») и живут по другим правилам: чанкинг с
родитель-ребёнок связями, бюджет токенов, cross-encoder/LLM-реранк, источники и коннекторы — тяжёлый,
латентность-терпимый конвейер с другой метрикой и другими потребителями.

В `ADR-007 §Decision` эти два продукта были объединены: «два профиля (precision/recall), общий S0/S2/S3,
два потребителя» — `POST /v1/memory/search` → `searchMemories()` и `POST /v1/context/query` → `retrieve()`.
Реализация показала цену объединения:

| | memory-путь | documents-путь |
|---|---|---|
| корпус в этой инсталляции | `memories` = **10 199** | `documents` = **2**, `chunks` = **0** |
| измеряется бенчмарком | да (54 вопроса, baseline `recall@10` 0.787, `qa/baseline-2026-09-24.json`) | **нет** — ни одного вызова `/v1/context/query` в `run.py` |
| критерий по ADR-010 §8 п.1 | объявлен | **объявить нечем** (нет корпуса и набора) |
| объём кода | ~1 000 строк монолита + слои | **4 615** строк движка (`retriever.ts` 2010, `chunker.ts` 701, `ingestion-queue.ts` 530, `ingestion-profiles.ts` 435, `compressor.ts` 371, `ingest.ts` 365, `oracle-select.ts` 203) + **6 548** строк коннекторов (22 файла) |
| поверхность API | `/v1/memory/*` | `/v1/context/query` + **11** маршрутов `/v1/sources/*` |
| схема | `Memory`, `MemoryRelation`, … | `Source`, `SourceVersion`, `Document`, `Chunk`, `ChunkMemory`, `IngestionJob` |

Следствие: 9 из 15 ADR-файлов частично описывают документную подсистему, `ADR-013 §Pending` просит
внедрять окна в `retriever.ts` (правка без метрики — по ADR-010 §8 п.1 даже неgradable), а `ADR-014`
держит документные модули в карте перехода. Работа идёт в подсистему, которую нельзя ни измерить, ни
закрыть критерием.

## Decision

**1. Граница продукта.** Margo — сервис накопления, отдачи и модерации **памятей**. RAG (загрузка
документов, чанкинг, контекст-пакинг, источники/коннекторы) — **вне области Margo**; при необходимости
это отдельный сервис/пакет со своими метриками, а не второй путь внутри одного retrieval-пайплайна.

**2. Разные профили нагрузки — не оптимизация одного пайплайна.** Памяти вызываются и обновляются на
каждый вызов агента; RAG — тяжёлый и латентность-терпимый. Объединение в один S0/S2/S3 с общими модулями
(ADR-007) **отклонено**: у них разные бюджеты латентности, разные единицы ответа (память против чанка) и
разные метрики (recall@10 фактов против качества контекста при бюджете токенов).

**3. Памяти несут подсказки об источниках — как обычный контент памяти.** Память вправе говорить, **что**
искать, **где** и **когда**: «SLA по доступности описан в platform-handbook, раздел uptime, действует с
2026-06», «конфиг сборки — в репозитории X, файл Y». Такая подсказка — не отдельная сущность и не ссылка
на чанк: это контент памяти, который проходит ровно тот же путь, что и любая другая память — извлечение
(ADR-002), типизацию, скоупы, validity/supersession, дедуп, гигиену (ADR-009), фильтрацию и ранжирование
при retrieval и **модерацию** (продуктовая цель Margo). Ничего нового под это не нужно: указатель живёт
текстом и метаданными памяти, а не связью с внешней таблицей. Памяти при этом остаются небольшими — это
утверждения, а не контейнеры информации, поэтому чанкинг им не нужен по построению.

Что именно исключено и поэтому вырезается: **корпус документов** (таблица `documents`), **чанкинг и
чанк-уровневый поиск** (`chunks`, `parentChunkId`, `section_path`), **связь память ↔ чанк** (`ChunkMemory`)
вместе с шагом `injectSourceChunks` (`search.ts:468, 580, 850`), **источники как сущность** (`sources`,
`source_versions`, sync/restore/versions) и **загрузка** (ingestion, коннекторы). Памяти, ссылающиеся на
внешние материалы, остаются — исчезает только машинерия, которая эти материалы добывала, резала и хранила.

**4. Вырезаем, а не помечаем deprecated-in-place.** Код документной подсистемы удаляется целиком
(см. §Implementation Impact). Для внешних потребителей это breaking: `QueryResult`/`context.query` в SDK,
payload MCP, `search_documents` в research-agent уходят — фиксируется версией SDK, а не «тихо живёт».

**5. Остаётся без изменений:** write-path и one-pass экстракция (ADR-002), Dreamer (ADR-003), hygiene
(ADR-009), benchmarking и гейт (ADR-010), телеметрия (ADR-011), провайдеры (ADR-012 — кроме
cross-encoder-реранка, см. ниже), memory-retrieval с окном (ADR-013 в memory-части), шаги ADR-014 — только
memory-часть.

## Implementation Impact

**Удаляется (шаги 2–6 ниже):**

| Что | Где |
|---|---|
| Движок документов | `engine/retriever.ts`, `compressor.ts`, `chunker.ts`, `ingestion-profiles.ts`, `ingest.ts`, `ingestion-queue.ts`, `oracle-select.ts` |
| Коннекторы | `connectors/*` — 22 файла (github, gitlab, huggingface, notion, confluence, slack, discord, pdf, video, web, sitemap, url, arxiv, npm_package, pypi_package, dataset, database, html-structure, api_spec, playwright, text, github-tarball) |
| Эндпоинты | `/v1/context/query` (`routes.ts:956`), 11 маршрутов `/v1/sources/*` (`routes.ts:1672–2273+`), ingestion-часть (`routes.ts:663–827`) |
| Схема | Prisma `Source:51`, `SourceVersion:87`, `Document:124`, `Chunk:163`, `ChunkMemory:293`, `IngestionJob:443` |
| Контракты и охрана | `contracts/registry.mjs`, `security/route-controls.ts`, `api/app.ts`, `__tests__/hermes-contract.test.ts` |
| Клиенты | SDK (`index.ts:864`, `whisper.ts:852`, `core/client.ts:24`), MCP-payload, research-agent (`search_documents`) |
| Следы в memory-пути | `injectSourceChunks`, `ChunkMemory`, metadata-ключи чанков в инвариантах ADR-007 (`parent_chunk_id`, `section_path`, `heading_path`, `parent_content`/`parent_excerpt`) — убирается **связь с чанком**; подсказка об источнике остаётся контентом памяти (§Decision п.3) |
| Тесты | `retriever.test.ts` (54), `chunker.test.ts` (90), `ingestion-queue.test.ts` (120), `ingestion-profiles.test.ts` (149) + документные кейсы suite |

**Порядок (каждый шаг — отдельный коммит, тесты и гейт зелёные, шаг 5 — единственный destructive):**

1. **Граница** (docs-only): этот ADR + правка плана + пометки в ADR-007/013/014.
2. **Memory-путь чистого листа**: убрать `injectSourceChunks` и `ChunkMemory` из memory-пути; локатор источника — строкой в памяти. Приёмка: memory-тесты зелёные, `recall@10` = 0.787 против `qa/baseline-2026-09-24.json`.
3. **Эндпоинты**: удалить `/v1/context/query` и `/v1/sources/*`; обновить реестр контрактов, `route-controls`, `app.ts`, контрактный тест.
4. **Движок и коннекторы**: удалить 7 модулей и 22 коннектора + их тесты.
5. **Схема (destructive, отдельным шагом)**: миграция `DROP` для шести моделей; перед шагом — дамп БД; приёмка — `prisma validate` + сервер поднимается, memory-эндпоинты отвечают.
6. **Клиенты**: SDK/MCP/local/research-agent.
7. **Гигиена**: скрипты ingestion-сидов, документация (AGENTS.md — только с согласия пользователя); TD-003 закрыть как «снят удалением», TD-010 сократить по факту.

**Долг, который умирает или сокращается:** TD-003 (`SourceStatus` enum drift — существует только у
планировщика источников) закрывается удалением; TD-010 (`<=>` вне `db/vector.ts`, 27 вхождений — 16 из них
в `retriever.ts`) сокращается до остатка; область §Compliance ADR-006 сужается; `RerankProvider` в ADR-012
нужен только если кросс-энкодер остаётся у памяти (сейчас у памяти intent-реранк, не кросс-энкодер) —
уточняется в шаге 4.

## Alternatives Considered

- **A: оставить как есть, не развивать.** Ноль риска сейчас — но подсистему нельзя ни измерить, ни
  закрыть критерием; код гниёт, `ADR-013 §Pending` вечно висит, долг (TD-003/TD-010) растёт. Отклонено:
  «не развивать» уже стоит нам прогонов, которые ничего не проверяют.
- **B: вынести документы в отдельный пакет монорепо (`packages/rag`).** Сохраняет написанное (≈11 000
  строк), но тащит чужой продукт в общий CI, гейт и схему — то есть сохраняет именно ту связанность,
  которую мы убираем. Отклонено решением пользователя; зафиксировано как путь, если RAG понадобится снова.
- **C (выбрано): вырезать целиком.** Репо = продукт, схема = продукт, гейт = память.

## Falsification Criteria

Объявлены по ADR-010 §8 п.1 — `{baseline-файл, метрика, статистика, протокол, допуск, направление}`.

- **Memory-путь не пострадал**: `recall@10` = 0.787 (baseline `qa/baseline-2026-09-24.json`, одиночный прогон — сьют детерминирован, допуск −2 п.п., выше лучше), протокол `python3 scripts/benchmark/run.py --suite retrieval --k 10`, гейт ADR-010 — PASS.
- **Схема чиста**: `prisma validate` проходит; в БД после шага 5 нет таблиц `documents`, `chunks`, `sources`, `source_versions`, `chunk_memories`, `ingestion_jobs`.
- **Следов не осталось**: `context/query`, `packContext`, `chunkText`, `connectors/` не встречаются вне `architecture/` и истории git (grep-критерий, выполняется на шаге 7).
- **Продукт жив**: сервер поднимается, `/v1/memory/search` и `/v1/memory/profile/:user/ask` отвечают, диалектика работает (интеграционный тест зелёный).

Если после вырезания memory-функциональность теряется (recall@10 падает, диалектика или write-path ломаются)
— решение пересмотреть.

## Related ADRs

- **ADR-007** — сужается до одного входа (memory); документные слои и второй потребитель сняты.
- **ADR-013** — §Pending про `retriever.ts` S2/S3 снят; окно живёт в memory-пути (S1 сделано, S2/S3 — в ADR-014 шагах).
- **ADR-014** — карта модулей сокращается до memory-части (`recall/lexical`, `fusion`, `rerank/intent`, …); документные модули `rerank/cross-encoder`, `delivery/pack`, `recall/semantic(documents)` уходят.

- **ADR-012** — провайдеры: `EmbeddingProvider` нужен памяти; `RerankProvider` (кросс-энкодер) — под вопросом шага 4.
